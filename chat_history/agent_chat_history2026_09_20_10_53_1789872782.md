你应该是想问 **SWE-bench**（可能打错成 sweb ench 了）。

**SWE-bench 是什么：**
SWE-bench 是一个用于评估大语言模型（LLM）**解决真实软件工程问题**能力的基准测试。核心信息如下：

- **来源**：由普林斯顿大学等团队在 2023 年提出（论文 *SWE-bench: Can Language Models Resolve Real-World GitHub Issues?*）
- **任务形式**：给模型一个真实的 GitHub 仓库 + 一个真实的 issue（问题报告），让模型生成一个 patch（代码修补），去修复这个 issue。
- **数据来源**：来自 12 个流行的 Python 开源项目（如 django、sympy、scikit-learn、matplotlib 等）的真实 issue 和对应的 PR。
- **评测方式**：模型生成的 patch 会被自动应用，然后运行该项目的测试用例，通过则算解决（resolved）。

**几个变体：**
- **SWE-bench**（完整版）：约 2294 个任务
- **SWE-bench Lite**：300 个任务的精选子集，用于低成本快速评测
- **SWE-bench Verified**：由人工筛选验证过的 500 个高质量任务，被广泛用于评测前沿模型（如 GPT-4、Claude 等）
- **SWE-bench Multimodal / Multilingual**：扩展到多模态、多语言

**为什么重要：**
它比传统代码生成 benchmark（如 HumanEval）更"真实、更难"，因为它要求模型理解整个仓库上下文、跨文件定位 bug、写出能通过测试的补丁。目前顶尖模型在 SWE-bench Verified 上的解决率大约在 50%–70% 区间（且仍在快速上升）。

**和你当前项目的关系：**
你这个项目本身就是一个 agent（`My_agent.py`），SWE-bench 经常被用作这类**代码 agent** 的评测基准——也就是给 agent 一个 issue，让它自主定位、修改、测试。如果你是想让自己的 agent 去跑 SWE-bench，或者对标它的能力，那这就是个很贴合的方向。
